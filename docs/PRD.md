# プロダクト要件定義書（PRD）
## AI投資判断支援ツール

**作成日**: 2026-05-06  
**ステータス**: 要件確定・実装待ち

---

## 1. プロダクト概要

### 目的
決算短信をトリガーにしたスイングトレードの意思決定を、AIとの対話を通じて支援する。  
「AIにスコアを出してもらって機械的に買う」のではなく、**AIを壁打ち相手として自分の判断力を育てながら運用する**ことを本質的な目的とする。

### ユーザー
- 個人投資家（優待株・インデックス投資の経験あり）
- PBR・PERなど基本的な財務指標の知識あり
- スイングトレードは未経験、まず怖さを減らしたい

### 投資スタイル
- **手法**: スイングトレード（数日〜数週間の保有）
- **戦略**: パターンX（決算発表後のリアクション型）
  - 決算発表 → 内容をツールで分析 → 翌日以降の値動きを狙う
- **規模**: 1銘柄あたり数万〜数十万円、ポートフォリオ合計100万円規模

---

## 2. フェーズ設計

### Phase 1（現在）：学びながら使う
- AIが決算内容を財務・市場・リスクの3視点でレポート生成
- ユーザーが「この数字はなぜ重要か」などをAIに質問して理解を深める
- 決算短信のどの部分を重要視するか、他の投資家は何を見ているかを体得する

### Phase 2（慣れてから）：自分の仮説をAIにレビューさせる
- 「自分はこれを買いだと思うが…」と入力するとAIが多角的に反論・補強
- 自分の投資判断の精度を上げる

---

## 3. 対象銘柄

### 対象セクター（東証33業種区分）
1. 電気機器
2. 食料品
3. 情報・通信業
4. 小売業
5. サービス業
6. その他製品（ゲーム・玩具等を含む）

### 銘柄選定方法
- **優先**: スクリーニング（直近3日以内にEDINETへ決算短信を提出した銘柄一覧）
- **併用**: 手動入力（企業名または証券コードで個別指定）
- 例：「任天堂の最新情報で分析したい」→ 証券コード7974でEDINETから最新書類を自動取得

## 4. AI設計

### 分析フロー

```
[Step 1] スクリーニング
  直近3日以内に決算短信を提出した対象6セクターの銘柄一覧を表示

[Step 2] 銘柄選択 → 自動レポート生成
  財務アナリストAI    : 売上・利益・前期比・ガイダンス評価
  市場アナリストAI    : 株価推移・出来高・短期モメンタム評価
  リスクマネージャーAI : 下落シナリオ・リスク要因の整理
  統合AIエージェント  : 3者を踏まえたスイング観点での総合判断

[Step 3] 対話フェーズ
  ユーザーが質問・仮説を入力 → AIが追加分析・反論・補強
```

### AI役割別プロンプト設計方針

| 役割 | 評価観点 | アウトプット |
|---|---|---|
| 財務アナリスト | 売上高・営業利益・前期比・通期ガイダンス・自己資本比率 | 業績の強弱判定と根拠 |
| 市場アナリスト | 株価推移・出来高変化・セクターモメンタム | 短期の需給・タイミング評価 |
| リスクマネージャー | 下落シナリオ・リスク要因・損切りライン目安 | リスクの定量・定性評価 |
| 統合エージェント | 上記3者の統合 | スイング観点でのBuy/Hold/Avoid判定と理由 |

## 5. UI設計

### 形式
- **Streamlit**によるWebアプリ（チャット＋グラフ＋レポートを1画面に統合）
- ブラウザで操作、ローカル環境で動作

### 画面構成（3画面）

#### 画面1：スクリーニング
- 直近3日以内に決算短信を提出した銘柄を自動取得・一覧表示
- セクター絞り込みフィルター
- 銘柄名・証券コードの手動入力フォーム
- 選択した銘柄の「分析する」ボタン

#### 画面2：AIレポート
- **上部**: 売上・営業利益の推移グラフ（棒グラフ）、株価チャート（折れ線）
- **中部**: 財務 / 市場 / リスク の3視点レポート（タブ形式）
- **下部**: 統合AIの総合判断（Buy/Hold/Avoid + 理由 + 注目ポイント）
- HTMLレポートとして保存・出力も可能

#### 画面3：対話チャット
- レポート内容を文脈として保持したままAIに質問できる
- 「この銘柄、買いだと思うんだけど」→ AIが多角的にレビュー
- Phase 2では自分の仮説を持ち込んでレビューを受ける場として活用

## 6. データフロー

```
EDINET API
  → 決算短信PDF取得（対象6セクター、直近3日 or 個別指定）
  ↓
pypdf
  → PDFテキスト抽出
  ↓
Gemini API（役割別プロンプト × 4回）
  → 財務 / 市場 / リスク / 統合 の各レポート生成
  ↓
ChromaDB
  → 分析結果を保存（過去の同企業との比較に活用）
  ↓
Streamlit UI
  → グラフ描画（Plotly）＋レポート表示＋チャット
```

---

## 7. 技術スタック

| 役割 | 技術 | 備考 |
|---|---|---|
| UI | Streamlit | チャット・グラフ・レポートを統合 |
| AI | Gemini 2.0 Flash（google-generativeai） | 長文PDF処理に強い、低コスト |
| データ取得 | EDINET API | 公式・無料。APIキー取得済み |
| PDF解析 | pypdf | 軽量、既存requirements.txtに含む |
| ベクトルDB | ChromaDB | 過去分析の保存・企業間比較 |
| グラフ | Plotly | インタラクティブ、Streamlitと相性良い |
| 環境変数 | python-dotenv | .envからAPIキー読み込み |
| コンテナ | Docker + docker-compose | 既存構成を修正して流用 |

## 9. 実装ステップ

| Step | 内容 | 優先度 |
|---|---|---|
| 1 | 環境構築（Docker構成をStreamlit用に変更、requirements.txt更新） | 最高 |
| 2 | EDINET連携（スクリーニング＋個別企業の最新書類取得） | 最高 |
| 3 | AIレポート生成（4役割のプロンプト設計＋Gemini API連携） | 高 |
| 4 | グラフ・可視化（売上・利益推移、株価チャート、スコアレーダー） | 高 |
| 5 | 対話チャット機能（レポート文脈を保持したStreamlitチャット） | 中 |
| 6 | ChromaDB連携（過去分析の保存・比較機能） | 中 |
| 7 | HTMLレポート出力 | 低 |

---

## 10. 制約・注意事項

- EDINET APIは「発表前の決算スケジュール」は取得不可。直近提出書類の取得のみ対応。
- 本ツールの分析結果は投資判断の補助情報であり、売買の最終判断は必ずユーザー自身が行うこと。
- APIキー（GOOGLE_API_KEY、EDINET_API_KEY）は`.env`で管理し、gitにコミットしないこと。
